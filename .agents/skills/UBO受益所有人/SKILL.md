# UBO 受益所有人 · CISP MCP 版

输入企业名称、统一社会信用代码、注册号或组织机构代码，生成与参考成品同篇章、同表格、同信息密度的完整 Markdown 报告。只替换企业事实与结论，不复制参考企业的数据。

## 强制边界

1. 只调用连接标识为 `cisp-mcp` 的 MCP 工具。不得使用网络搜索、浏览器、其他企业数据库、用户未提供的材料或模型记忆补数据。
2. 只调用本 Skill 列出的专用工具。不得调用通用 `query_cisp_product`，也不得用尚未接入 MCP 的产品码绕过专用工具。
3. 工商深度是主体底座。`p0010058_query_business_basic_deep` 不存在、失败、无结果或主体不一致时立即停止，不生成报告。
4. MCP 工具、产品码、JSON 路径、状态码、额度、鉴权和调用过程仅用于内部执行，严禁写入客户报告。
5. 仅交付 Markdown。用户未指定路径时直接在聊天内输出；用户指定 `.md` 路径时保存并返回绝对路径链接。

## 必须读取的引用

- 开始查询前完整读取 [API 覆盖、字段映射与接口缺口](references/api-coverage-and-gaps.md)，按其中的现有工具和字段边界取数。
- 生成报告前完整读取 [固定报告模板](references/report-template.md)，严格保持标题、章节、子章节、表头、提示段、数据来源、适用标准和免责声明的顺序。

## 状态语义

- `result_code == "00000"` 只表示网关调用成功，继续检查 `product_status`。
- `product_status == "4"` 表示成功有结果；数组仍可能为空，空数组只写“本次未返回相关记录”。
- `product_status == "1"` 表示本次无结果，不得改写成“经全量扫描确认不存在”。
- `product_status == "3"` 表示产品查询失败，写“当前不可用”或“本次未完成核验”，不得写成否定事实。
- 原始响应中的摘要或提示语只有在明确属于目标主体且语义完整时才可忠实转述；不得补写“全量扫描”“官方确认”等上游未返回的措辞。

## 工作流

### 1. 锚定唯一主体

1. 完整名称或代码直接调用工商深度；简称、品牌或同名歧义先做名称消歧。
2. 从工商深度的唯一匹配记录确认规范企业全称、统一社会信用代码、登记状态和法定代表人。多条合理候选无法消解时停止并请用户确认。
3. 调用工商照面交叉核验名称与信用代码；只接受企业全称完全一致且双方非空信用代码一致的记录。
4. 所有后续调用统一使用规范企业全称或已核验信用代码。任一结果主体不一致时舍弃该结果并记录维度失败。

### 2. 获取完整工商底座

1. 保存工商深度中的 `basicList`、`shareholderList`、`personList`、`entInvItemList`、`filiationList`、`alterList`。
2. 调用工商简项基础批次：
   `types=["basic","shareholder","person","alter","filiation","foreignInvestment","yearReportPaidUpCapital"]`。
3. 返回体过大时按主题拆为多次调用，但不得删减上述类型。使用 `changeRecords` 补充变更总量与分类需要时，再单独调用 `types=["changeRecords"]`。
4. 两个工商产品合并时按稳定业务键删除完全重复记录，不把同名但金额、比例、日期或职务不同的记录合并。
5. 股东、人员、投资、分支和变更数量只有在完整列表或明确总量字段可得时才写精确总数；否则写“本次取得 N 条”，不得宣称全量。

### 3. 识别 UBO 与实际控制人

依次调用直接结论、按目的选择的 UBO 详版/非详版、UBO 全路径、受益股东明细节点、实际控制人明细、疑似实控路径和股权穿透骨架，形成内部核验矩阵：

- 生成完整报告、审计留档、需要递归路径或关键管理人员兜底时，调用统一工具并设 `edition="detailed", include_paths=true`。
- 快速识别、独立互证或需要 `bnfCat` 判定依据时，设 `edition="standard"`；只需要受益人名单时可设 `include_paths=false`。
- 不得为同一目的无差别同时调用详版和非详版；只有结果冲突、详版失败或用户明确要求双产品互证时才补调另一版。

| 判断 | 首要证据 | 互证证据 | 输出边界 |
| --- | --- | --- | --- |
| 受益所有人 | 详版/非详版的最终受益人结论与 UBO 全路径聚合结论 | 受益股东明细节点、实控/受益人直接结论、工商直接股东 | 只输出产品明确返回的自然人、角色、判定依据和原始聚合比例；明细节点不等同于完整路径 |
| 实际控制人 | 实际控制人明细中的控制人、聚合比例和控制路径 | 实控/受益人名称结论、受益股东标签、疑似实控路径、股权穿透 | 明细或名称型直接结论可写“实际控制人”；疑似产品只能写“疑似” |
| 高管层兜底 | UBO 产品明确返回的管理人员名单或明确兜底提示 | 工商主要人员职务 | 工商 `personList` 只核验姓名与职务，不得自行把全体董监高认定为 UBO |
| 未识别结论 | 成功产品明确返回空结论或否定摘要 | 股东最大比例、低于阈值路径 | 产品失败、空数组或路径中断不得写“未发现” |

识别顺序固定为“股权/权益标准 → 其他控制方式 → 产品明确给出的高管层兜底”。25% 是报告中的识别阈值，不得因浮点误差把恰好 25% 改写为高于 25%；如原产品表述为“25% 以上”，报告沿用原产品口径，不自行解释是否含本数。

### 4. 计算和数值纪律

1. 直接持股、最终受益股份、控制比例、表决权比例、持股数和日期逐字保存原始字符串，不截断、不补零、不四舍五入。
2. 不将多层持股比例相乘，不将多条路径求和，不用直接持股倒推间接持股、收益权或表决权。
3. 仅允许基于完整直接股东列表计算最大股东、排序和股东类型数量；使用十进制定点比较。列表不完整时不得做完整性结论。
4. 实缴率仅在注册资本与实缴资本的币种、单位、时点和经济含义一致时计算；否则写“无法比较”。
5. “持股数（股）”只填产品明确返回的股数。认缴出资额不得改名为股数；未返回股数写“未披露”。
6. 表决权、收益权和受益所有权形成日期没有直接字段时统一写“未披露”，严禁用持股比例或成立日期代替。
7. 置信度只衡量本次证据覆盖：完整列表的机械计数且多产品一致可写 `100%`；其余结论写 `—`，不得凭主观感觉生成百分比。

### 5. 生成各章节

严格使用模板，按以下来源填充：

- 报告头部、§3.1：规范主体与工商基本信息。
- 执行摘要：只压缩已确认的 UBO、实际控制人、股东结构、对外投资、治理变更和资本事实。
- §1：保留模板用途和三步法说明；数据源名称改为 `cisp-mcp`，不得声称来自企查查或未核验的上游。
- §2.1：保留模板识别方法；将“穿透计算引擎”表述为 CISP 产品聚合结果，不声称自行重算。
- §2.2：完整报告优先使用统一 UBO 工具的详版结果，并与 UBO 全路径结论互证；需要判定依据或快速复核时选择非详版并读取 `bnfCat`。再用受益股东明细节点的 `benifitTag`、`percentTotal`、`pathLevel`、`pathCount` 做独立互证；节点聚合结果不得自行还原完整路径。无结果时保留一行占位。
- §2.3：优先列示实际控制人明细产品返回的 `controller`、原始 `percent` 和 `controlPathList`，再与名称型直接结论及疑似路径互证；不得把聚合比例拆成直接持股、总持股或表决权。只有疑似候选时明确标“疑似”，不得升级。
- §2.4：只列 UBO 详版或其他 UBO 产品明确给出的关键管理人员；用工商人员数据补职务但不扩充名单。
- §3.2：完整列示本次取得的全部直接股东，不默认截断；按可解析持股比例降序，无法解析者保持接口顺序置后。
- §3.3：完整列示主要人员；相同姓名、相同职务的完全重复行可去重。
- §3.4：完整列示对外投资；同名企业不同金额或时点不得擅自合并。
- §3.5：完整列示分支机构；负责人、地区、成立日期、状态缺失时写“未披露”。
- §3.6：写明累计数量与实际展示范围，默认展示最近 10 条；只有完整列表时才按变更项目汇总数量。
- 数据来源与免责声明：只写本次实际使用的 `cisp-mcp` 数据维度和生成时间。

### 6. 执行摘要与深度推演纪律

- 一句话结论必须回答：企业类型和股权集中度、识别到几名 UBO、是否有实际控制人、是否触发管理层兜底。
- “股权高度分散”“无单一大股东”等判断必须有完整直接股东列表和最大股东比例支持。
- “前十大均为某类机构”“对外投资聚焦某行业”“治理稳定”等归纳必须逐条可回溯到表格事实；无法完整分类时删除该句。
- 变更任期只可从明确的法定代表人变更日期计算，并使用报告生成日作为截止日；结果标“约”。无明确起始日期时不计算。
- 待核验事项优先列未披露的一致行动、表决权委托、协议控制、代持、合伙平台穿透断点、境外穿透和产品冲突；没有事实依据时不点名具体主体。

## 缺失与冲突处理

1. 字段缺失写“未披露”，成功空列表写“本次未返回相关记录”，调用失败写“当前不可用”。三者不得互换。
2. UBO 产品之间名称、角色或比例冲突时并列原值，在执行摘要写“产品结果存在差异，待人工核验”，不自行选边。
3. 直接股东比例与 UBO 聚合比例不同不构成天然冲突；分别保留各自口径。
4. 工商股东列表与股权穿透第一层不一致时，股东表以工商当前股东为主，穿透结果只用于 UBO 路径，并披露“路径时点/口径待复核”。
5. 境外、循环持股或路径中断时停止在最后可核验节点，不补出自然人终点。

## 最终验收

交付前逐项检查：

- 标题与章节顺序和模板完全一致；没有新增、删除、合并或改名。
- 企业名称、信用代码和全部扩展结果属于同一主体。
- UBO、实际控制人和管理层兜底均有对应产品直接证据。
- 所有比例、金额、日期、人数、股东数和投资数可回溯到本次数据或允许的明确计算。
- 未把认缴额写成股数，未把持股比例写成表决权，未把疑似实控人写成实控人。
- 最终报告未出现工具名、产品码、字段路径、状态码、企查查数据源声明或调用过程。
- 数据来源明确为本次实际使用的 `cisp-mcp` 数据，免责声明完整保留。
- 输出是完整 Markdown，不只返回摘要或执行过程。
