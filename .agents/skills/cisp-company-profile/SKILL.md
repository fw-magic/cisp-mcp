# CISP 企业一页纸画像

## 目标

围绕一个已确认的企业主体，生成紧凑、事实化、带数据边界说明的企业画像。默认使用标准版和 `both` 格式：在聊天中返回精简摘要，同时生成可下载、可归档的多页 A4 PDF。PDF 第 1 页是一页式执行看板，后续页面承载详细事实和证据说明。

本 skill 依赖 CISP MCP。不同 Agent 宿主可能为工具名添加服务器前缀；按下文列出的规范工具名后缀匹配工具即可。

## 输入和模式

至少需要以下任意一项：

- 企业全称；
- 统一社会信用代码；
- 工商注册号；
- 组织机构代码。

支持三种模式：

| 模式 | 触发方式 | 查询范围 |
| --- | --- | --- |
| 精简版 | 用户明确要求“精简”“快速”“只看工商” | 工商深度信息 |
| 标准版 | 默认 | 工商深度 + 商标 + 专利 + 软件著作权 + 作品著作权 + 许可 + 荣誉资质 + ICP |
| 完整版 | 用户明确要求“完整”“深度”，或明确要求关联关系/近期舆情 | 标准版 + 投资与任职关联 + 近 90 天舆情 |

支持三种交付格式：

| 格式 | 触发方式 | 交付 |
| --- | --- | --- |
| `both` | 默认；或用户要求“摘要加 PDF” | 聊天精简摘要 + PDF |
| `md` | 用户明确要求 Markdown、文本、不要文件 | 完整 Markdown，不生成 PDF |
| `pdf` | 用户明确要求只要 PDF、只要文件 | 最简聊天提示 + PDF |

自然语言与 `--format md|pdf|both` 等价。没有明确格式时不得追问，直接使用 `both`。

如果用户只给出企业简称、品牌名或可能重名的名称，先消歧。除非缺少可识别的企业信息，不要因版式或字段偏好阻塞执行。

## 工作流

### 1. 锚定企业主体

1. 用户提供统一社会信用代码、工商注册号、组织机构代码或明确完整企业名称时，直接调用 `p0010058_query_business_basic_deep`。
2. 用户提供简称、品牌名或模糊名称时，先调用 `p0010068_fuzzy_search_company_name`。
3. 模糊查询只有一个明显匹配项时，用其企业全称继续；存在多个合理候选时，列出少量候选并请用户确认，不得擅自选择。
4. 工商深度结果返回后，以 `data.basicList[0].orgName` 和 `creditCode` 作为后续查询的主体锚点。名称优先使用规范企业全称。
5. 工商深度结果与用户指定主体不一致，或没有返回可确认主体时，停止画像生成并说明原因。

不要使用从 CISP 查询结果中取得的法人、证件号等信息反向调用二要素或三要素核验工具。核验只能基于用户自行提供的材料，且不属于本画像的默认流程。

### 2. 调用模式对应的工具

先完成主体锚定，再执行其余调用。宿主支持并行工具调用时，可并行查询互不依赖的维度。

精简版仅调用：

- `p0010058_query_business_basic_deep`

标准版在工商深度查询之外调用：

- `p0010073_query_trademark_info`
- `p0010078_query_patent_info`
- `p0010074_query_software_copyright_info`
- `p0010075_query_work_copyright_info`
- `p0010084_query_license_info`
- `p0110003_query_honor_qualification_info`
- `p0010076_query_icp_filing_info`

对支持分页的标准版工具统一传 `page_no="1"`、`page_size="5"`。用响应中的 `totalCount` 表示总量；第一页记录只作为接口首批返回的示例，不得把当前页条数当作总量，也不得无依据称其为“最新记录”。

完整版再调用：

- `p0020021_query_single_point_related_info`，传 `relation_direction="1"`，因为完整版同时覆盖投资和任职关系；
- `p0050007_p0050008_query_public_opinion_info`，以执行当天为结束日期、向前推 90 个自然日为开始日期，日期格式 `yyyy-MM-dd`；传 `page_no="1"`、`page_size="10"`、`max_details=3`，不默认设置情感过滤。

用户单独指定舆情时间范围时，以用户范围为准。用户单独要求“只查投资”或“只查任职”时，分别使用 `relation_direction="2"` 或 `"3"`。

不要调用 `query_cisp_product` 来替代上述专用工具。

### 3. 提取和归纳

执行前读取 [字段映射](references/field-map.md)。遵循以下原则：

- 只陈述响应中存在的事实，保留原始日期、金额、币种和比例显示值；
- 股东比例可解析时可用于排序，但输出仍保留原字符串；不可解析时保持接口顺序；
- 每张明细表最多展示 5 行，风险或舆情重点最多展示 3 条；
- 工商变更、许可、荣誉、知产等列表只有在日期字段足以证明时才称“最新”；
- 舆情是公开信息线索，不等同于司法或监管事实；
- 不推断最终受益人、实际控制人、间接持股、偿债能力、估值、融资结论或商业合作结论；
- 不生成黑箱综合评分，不替用户作“准入/拒绝”“安全/高危”的最终决策。

风险事实分两层归纳：

- 重点关注：非正常经营状态、吊销或注销日期、失信被执行、被执行、严重违法、经营异常、清算；
- 提示关注：行政处罚、股权冻结或出质、动产抵押、司法协助、近期重大工商变更。

风险字段为空只表示“本次查询未返回相关公开记录”，不能表述为“无风险”“完全合规”。

### 4. 构建统一证据模型

查询完成后先整理统一证据模型，再生成任一交付格式。不要让 Markdown 和 PDF 分别归纳原始响应，以免同一事实出现不同口径。

执行前读取：

- [报告模板](references/report-template.md)：聊天摘要和完整 Markdown 的固定骨架；
- 需要生成 PDF 时再读取 [PDF 证据模型](references/pdf-evidence-model.md)。

证据模型至少包含：

- 报告元数据、规范企业名称、统一社会信用代码、查询时间、模式和报告编号；
- 主体、经营摘要、股东、人员和经营网络；
- 资产资质、风险事实、近期变更；
- 完整版的关联和舆情；
- 成功、空结果、失败维度和数据边界。

报告编号使用 `CISP-CP-{统一社会信用代码}-{YYYYMMDD-HHMMSS}`。信用代码未披露时使用规范企业名称的安全短标识，不得留空。

### 5. 生成交付物

#### `both`

1. 依据证据模型生成约 300–600 个汉字的聊天摘要，保留主体状态、业务定位、核心数量、1–3 条关注事实和数据边界。
2. 把证据模型写入 `tmp/pdfs/{report-id}.json`。
3. 把 `<skill-dir>` 解析为当前 `SKILL.md` 所在目录，不假设 skill 安装在固定项目路径，然后调用：

```bash
uv run python <skill-dir>/scripts/render_company_profile_pdf.py \
  --input tmp/pdfs/{report-id}.json \
  --output output/pdf/{规范企业名称}-企业画像-{模式}-{YYYY-MM-DD}.pdf
```

4. 检查命令成功且 PDF 文件存在；有 `pdfinfo` 或 `pypdf` 时验证文件可解析。
5. 有 `pdftoppm` 时把全部页面渲染到 `tmp/pdfs/{report-id}/`，逐页检查中文、表格、裁切、页码和章节过渡。
6. 视觉验收通过后删除本次 JSON 和渲染 PNG，保留最终 PDF。
7. 最终回复附绝对路径的可点击 PDF 链接。

#### `md`

按 [报告模板](references/report-template.md) 输出完整 Markdown，正文优先保持在约 900–1500 个汉字。数据较多时保留总量和关键事实。

#### `pdf`

按 `both` 的 PDF 流程生成文件；聊天仅说明企业名称、查询日期、模式、PDF 链接和必要的数据缺口。

PDF 固定为：首页执行看板、主体与经营、股权治理与经营网络、经营资产与资质、风险与变更、数据来源与证据说明；完整版在风险前增加关联与舆情。没有有效内容的章节直接删除，不得为了凑结构编造数据。

## 缺失、空值和失败处理

明确区分三种状态：

- 成功但列表为空：写“本次查询未返回相关公开记录”；
- 工具调用失败或不可用：写“该维度查询未完成”，附简短原因；
- 字段未返回或值为空：写“未披露”或不展示该字段。

某个扩展维度失败时，继续生成其他已取得维度的画像，并在“数据说明”中列出失败项。工商深度查询失败或主体无法确认时，不生成貌似完整的画像。

若找不到 CISP MCP 或所需工具，说明缺少 CISP MCP 依赖和缺失的工具名；不要自动改用互联网搜索或其他数据源补齐。

PDF 渲染失败时：

1. 不循环重试；
2. 删除不完整 PDF 和本次临时文件；
3. 明确写“PDF 生成未完成：{简短原因}”；
4. 自动回退完整 Markdown，不能只交付一条失败提示。

宿主没有文件系统、Python 或 ReportLab 时按同一规则回退 Markdown，不尝试改造 MCP 工具返回二进制文件。

## 输出约束

- 使用中文，除非用户指定其他语言。
- 事实和研判分开表达；研判使用“提示关注”“可能需要进一步核验”等措辞。
- 不暴露身份证号、手机号等非必要个人敏感信息；只展示形成画像所需的企业公开信息。
- 在末尾列出已成功、空结果和失败的查询维度，形成最小证据链。
- PDF 是展示层，不得增加 Markdown 中没有证据支持的评分、图表结论或业务判断。
- 股东图表只使用可解析比例，标签仍保留接口原始比例字符串；不可解析时只保留表格。
- “企业一页纸”指 PDF 首页的一页式管理摘要，不限制整份 PDF 总页数。
- 用户追问某一项时，再展开对应接口返回的详细记录，不要在一页纸中倾倒全部原始数据。

## 示例触发语

- “用 CISP 快速看一下这家供应商，只要精简版。”
- “生成完整版公司画像，带关联企业和最近三个月舆情。”
- “生成标准版企业画像，只要 Markdown。”
- “给我摘要和可归档 PDF。”
