# 核验 API 产品数据源

## 目标

在新增 API 产品接入前，确认产品及其全部组件只依赖自有数据源。内部数据源白名单为 `{N300, N000, N400, N054}`。只有所有有效“数据源编码MR”均属于该白名单，才能判定为“自有数据源，可接入”。

## 输入与默认值

- 接受一个或多个严格符合 `^P[0-9]{7}$` 的产品码，可附带产品名称用于结果对照。
- 默认工作簿：`/Users/ice/Desktop/项目管理/API agent/API数据资产设计表 (1).xlsx`。
- 用户指定其他 `.xlsx` 路径时优先使用用户路径。
- 检查工作表：`个人编码`、`API企业编码上线`。用户写成“API 企业编码上线”时，仍以工作簿中的实际名称为准。
- 关键表头：`二级目录（产品）`、`产品编码MP（P+MD+4位）`、`数据源编码MR`。
- 始终使用 `spreadsheets:Spreadsheets` Skill 和其指定的 `@oai/artifact-tool` 只读载入工作簿；不得改用 `openpyxl`、`pandas` 或其他 Excel 库。

## 判定规则

将每个产品归入且仅归入以下状态之一：

| 状态 | 条件 | 接入结论 |
| --- | --- | --- |
| 自有数据源 | 至少取得一个有效编码，且全部编码都在 `{N300, N000, N400, N054}` | 可接入 |
| 含第三方数据源 | 任一有效编码不在 `{N300, N000, N400, N054}` | 不接入 |
| 数据源待确认 | 产品已找到，但产品分组没有任何有效数据源编码，或原值无法解析 | 暂停接入 |
| 产品未找到 | 两个工作表均无精确产品码 | 暂停接入 |

不得因为某一行命中内部数据源白名单就提前判定为自有数据源；必须检查产品分组内所有组件行。若产品在多个位置或两个工作表重复出现，合并全部命中分组后再判定，任一分组含第三方或缺失数据源都不能判为“可接入”。

## 工作流

### 1. 校验文件与产品码

1. 确认工作簿存在且可读，不创建副本、不导出、不保存。
2. 校验所有产品码格式；格式错误时逐项报告，不自行补位。
3. 只载入源工作簿并确认两个目标工作表存在。实际表名不一致时报告差异，不搜索相似工作表后静默替代。

### 2. 定位表头

1. 在每个目标工作表的表头行按完整文本定位关键列，不把列字母写死为唯一依据。
2. 当前表通常为：产品名称列 `C`、产品码列 `D`、数据源编码列 `K`；仍须以表头定位结果为准。
3. 任一必要表头缺失时停止该工作表的核验并报告结构异常。

### 3. 精确定位产品分组

1. 对产品码列做去除首尾空白后的精确匹配，不使用名称模糊匹配替代产品码。
2. 命中产品码的行是分组首行。
3. 从首行向下扫描，直到下一行产品码符合 `^P[0-9]{7}$` 为止；这一区间是该产品的完整组件分组。
4. 产品码后续组件行常为空，不得只读取首行，也不得遇到普通文本或空白就提前结束分组。
5. 记录命中工作表、Excel 行号范围、工作簿内产品名称。用户名称与工作簿名称不同时，以产品码为身份依据并报告名称差异。

### 4. 汇总数据源编码

1. 读取分组内每一行的“数据源编码MR”原值和行号。
2. 保留原值用于审计，同时从每个非空原值中提取全部 `N[0-9]{3}` 编码。
3. 去重后形成产品的数据源编码集合，但不要丢失原始行级证据。
4. 非空原值无法提取有效编码时，将该分组标记为“数据源待确认”，不得按空值忽略。

### 5. 判定并复核

1. 对合并后的全部编码执行判定规则。
2. 对“可接入”产品复核：编码集合非空，且不存在 `{N300, N000, N400, N054}` 之外的编码。
3. 对包含多个组件行或同时出现多个内部数据源编码的产品，列出完整行号范围和编码集合。
4. 使用 `workbook.inspect` 再检查每个命中的精确范围，确保产品码、产品名称与数据源编码对应无误。

## 输出要求

输出紧凑表格，至少包含：

- 产品码与工作簿产品名称。
- 命中工作表及行号范围。
- 去重后的“数据源编码MR”。
- 是否仅自有数据源。
- 接入结论与异常说明。

明确给出批量总论，例如“6 个产品均可接入”或“其中 2 个产品包含第三方数据源”。为每项工作簿事实提供最窄可靠的 Excel 文件引用，优先引用产品分组的精确单元格范围。不得把“未找到”或“无编码”描述为自有数据源。

## 完成条件

同时满足以下条件才算完成：

1. 两个目标工作表均已检查。
2. 每个产品码均有唯一状态，不漏项。
3. 每个命中产品的全部组件行均已纳入数据源集合。
4. 判定严格遵守 `{N300, N000, N400, N054}` 白名单，缺失和异常默认阻断接入。
5. 源工作簿未被修改、覆盖或导出。
