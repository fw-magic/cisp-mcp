## 页面与基础 token

- 页面固定为 Letter，215.9 × 279.4 mm；上、下边距 20 mm，左、右边距 25 mm；可用正文宽度 165.9 mm。
- 正文使用宋体或等价中文宋体 Regular，10.5 pt、固定行高 15 pt、段后 4 pt。
- 表格正文使用 9 pt、固定行高 12 pt；元信息使用 9 pt、固定行高 12 pt。
- 主标题使用真实中文标题字形，18 pt、黑色、粗体视觉、居中。
- 一级标题 14 pt，二级标题 12 pt；均使用真实中文标题字形与 `#4D6EEB`。一级标题段前 12 pt、段后 6 pt；位于页首时不额外制造空白。引用块竖线等非文字章节装饰同样使用 `#4D6EEB`。
- 表头使用主色的低饱和浅色 `#CED4EE` 实色底纹，文字黑色、真实中文 Bold、左对齐；普通数据行不得使用该底色。
- 表格使用黑色 0.5 pt 全网格；正文 Regular、左对齐、垂直居中。
- 不添加通用封面。每页统一绘制报告家族页眉页脚，且只能占用现有页边距，不得侵入或挤压正文区：页眉左侧为蓝色真实 Bold“水滴征信 MCP”，右侧为深灰色“审计留档”，下方绘制 0.5 pt 蓝色分隔线；页脚左侧为深灰色“cisp.zenitera.com · 水滴征信 MCP”，右侧为“第 N 页”，上方绘制 0.5 pt 浅灰分隔线。
- 页眉页脚左右边界与正文区一致，均为距页面左右侧 25 mm；页眉文字基线距页顶 9 mm、分隔线距页顶 12 mm，页脚分隔线距页底 12 mm、文字基线距页底 7.5 mm。页眉左侧品牌文字和页眉分隔线固定为 `#4D6EEB`，其他页眉页脚文字固定为 `#3F4E63`，页脚分隔线固定为 `#D9E2F0`。
- 页眉页脚必须在首页和后续页保持一致，页码从 1 连续递增。本报告不得覆盖文案、坐标或颜色，也不得增加报告专属页眉、页脚、页码、Logo 或其他页面装饰。

## 中文字体契约

- Regular、Bold 必须来自两个不同的真实 PostScript 字形；不得把同一 Regular 同时注册为 normal/bold，不得依赖阅读器合成粗体、描边、重复绘制或字号模拟。
- macOS 首选 `/System/Library/Fonts/Supplemental/Songti.ttc`：Regular 为 `STSongti-SC-Regular`（子字体 6），Bold 为 `STSongti-SC-Bold`（子字体 1）；标题可用 `/System/Library/Fonts/STHeiti Medium.ttc` 的 `STHeitiSC-Medium`（子字体 1）。
- 其他系统必须显式提供覆盖报告全部字符的 Regular 与 Bold 字体文件；使用字体 cmap 预检字符覆盖，使用字体元数据核验 PostScript 名不同。
- ReportLab 必须分别注册 Regular/Bold 并建立字体族映射。动态文本先做 XML 转义；Markdown `**` 只有语义作用，必须转换为真实 Bold 字形。
- 正式排版前生成只含“正文测试”和“粗体测试”的临时 PDF，核验两种字体资源并目视确认差异。失败即停止 PDF 流程。

## 表格与紧凑字段

- 本报告必须在列定义层提供绝对 mm 列宽，所有列之和必须等于 165.9 mm（允许计算误差 0.05 mm）；不得按内容自动估算、缩放或重分配。
- ReportLab 使用通用工具提供的标准 `Table`、`colWidths` 与 `repeatRows=1`；不得改用启用长表优化的 `LongTable`，避免分片高度计算越过页边距并覆盖页眉。HTML 使用固定布局与绝对 mm `colgroup`；DOCX 同时固定 `tblGrid/gridCol` 与各列 `tcW`。
- 表头跨页重复时必须保持相同浅蓝实色底纹、黑色 Bold 字体和列宽。
- 允许表格自然跨页；普通数据行必须整行移至下一页，只有单行本身高于一页可用正文区时才允许行内跨页拆分。不得为保住整表或章节起始而压缩字号、行距或列宽。
- 所有可能包含中文、企业名称、控制路径、关系说明或复核建议的表头和数据单元格必须使用 CJK 自动换行；不得使用 `LTR + splitLongWords=False` 承载这些内容，避免文字越过单元格边界。
- 编号、日期、纯数字短比例、置信度等紧凑字段仅在完整内容实测宽度不超过单元格可用宽度时保持单行；超过宽度时自动回退 CJK 换行。不得仅凭“该列通常较短”就对整列禁用换行。

## 自然分页

- 不使用 `KeepTogether`、`keepWithNext`、整块容器或手动分页符保护章节、段落、说明或表格起始部分。
- 不因避免断句、孤立标题或来源文字而移动整块内容；跨页表格只重复表头，不重复小节标题。
- 不得通过缩小字号、字符缩放、压缩行距或压缩段间距减少页数。
- 不得出现裁切、重叠、乱码、黑块或强制分页造成的异常空白。除最后一页外，后续仍有连续内容而当前页空白超过可用正文区约三分之一时，判定失败。

## 验收与交付

1. 对照本报告语义验收清单确认 PDF 与最终 Markdown 内容源、章节、字段、表头、原值和免责声明一致；PDF 阶段不得改写业务内容。
2. 检查每页 MediaBox 为 Letter；检查文本可提取，必备标题/表头存在，且不存在未替换占位符。逐页检查统一页眉、页脚均可提取，页码与实际页序一致且连续。
3. 检查 PDF 字体资源包含不同的中文 Regular 与 Bold PostScript 字形；抽查标题、表头、正文和数据的实际字重。
4. 检查表头非描边填充色为 `#CED4EE`，跨页重复表头颜色一致；普通数据行无该填色。
5. 把全部页面渲染为 PNG，逐页检查字体、字号、行高、边距、页眉页脚、页码、颜色、列宽、换行、分页、裁切、重叠、乱码、黑块、异常空白和免责声明。
6. 任一步失败时删除不完整 PDF、字体测试 PDF、预览图片和其他本次临时文件，输出同一内容源的完整 Markdown。验收成功后只保留最终文件和明确要求的测试资产。

## 本地工具

- 使用 `../scripts/report_pdf_toolkit.py` 的 `discover_font_spec()`、`register_chinese_fonts()` 完成字体预检与注册。
- 使用 `make_styles()`、`make_table()` 和 `draw_page_chrome()` 生成固定样式、重复表头与统一页眉页脚。
- 使用 `verify_pdf()`、`render_pdf()` 完成结构、字体、文本和逐页图片验收；失败时调用 `guarded_validate_or_fallback()` 清理并回退完整 Markdown。
- 不得从 `../scripts/` 之外加载 PDF 工具；本 Skill 必须可以独立复制、运行和验证。

## 内容源与固定层级

1. 先完成语义验收后的完整 Markdown，确认企业副标题、八项报告头部、执行摘要、八个业务章节和最终数据来源与免责声明齐全。
2. PDF 只排版该 Markdown 内容源，不重新归纳、删节、扩写、计算比例或调整章节顺序。
3. 主标题固定为“股权结构穿透分析”。企业完整登记名称是本报告自己的加粗居中副标题，不替换为客户名称层级。
4. 主副标题后固定展示：目标企业、统一社会信用代码、法定代表人、报告类型、报告生成、审计留档编号、穿透方向、控制权稳定性。八项标签使用真实 Bold，值使用 Regular。
5. “执行摘要”、一至八章和“数据来源与免责声明”为一级标题；3.1 至 5.2 等编号子节为二级标题。
6. 不添加额外封面、报告专属页面装饰、证据索引、接口明细或客户访前报告使用说明；只启用本文件定义的统一页眉页脚与连续页码。

## 专属段落与粗体白名单

- 执行摘要“一句话结论”使用左侧 2 pt 章节色竖线的引用块，不使用底色。“建议行动”标签单独一行，后续 1、2、3 三条分别换行展示；不得合并为一个连续段落。ReportLab 必须使用 `make_action_list()` 生成该区域。
- 各章表后说明、穿透提示、一致行动提示和关联交易提示使用较正文略小的 Regular 说明样式，并保持原篇章位置。
- 只允许主副标题、章节标题、八项元信息标签、“一句话结论”“建议行动”、表头和免责声明标签使用真实 Bold。实体名称、比例、置信度、说明和表格数据必须使用 Regular。
- “数据来源与免责声明”固定在第八章之后；数据来源为独立段落，免责声明保持四条编号列表。

## 专属语义验收

1. 顺序严格为主标题 → 企业副标题 → 八项报告头部 → 执行摘要 → 一至八章 → 数据来源与免责声明；没有新增、合并、重命名、调序或遗失提示语。
2. 核对执行摘要六项关键判断、三条建议行动、第三章三个子节、第四章三个子节、第五章两个子节和全部固定表头；确认三条建议行动各占一行。
3. 所有直接持股、总持股、最终受益股份、表决权、产品聚合比例和置信度沿用 Markdown 原始字符串；TopN 等允许计算项与 Markdown 一致。PDF 阶段不得重算、舍入、补零或补造未披露值。
4. 实际控制人、最终受益人、中间控制路径、一致行动边界、控制权脆弱性和关联交易边界继续执行 `SKILL.md` 的规则；不得引入 FACT/OPP/RISK、贷款营销、拜访问题或客户访前报告话术。
5. 股权全景跨页时逐页核对本文件定义的重复表头、绝对列宽、短比例与序号不竖排、长单元格自然换行；逐项抽查 4.2、4.3、六章表格的首尾行，确认文字未越过单元格边界、行与行之间无重叠；普通数据行不使用表头底纹。
6. 第八章后的数据来源与四条免责声明完整可提取、无裁切，并保持原提示语。

## 文件与回退

- 验收成功输出 `output/pdf/{company_name}-股权结构穿透分析.pdf`。
- 用户指定 Markdown、PDF 能力检查失败或本 Skill 的 PDF 流程任一步失败时，先删除本次不完整 PDF、字体测试文件和预览图片，再在聊天中输出同一内容源的完整 Markdown。
- Markdown 回退必须保留企业副标题、八项报告头部、执行摘要、八章和最终数据来源与免责声明，并说明：`PDF 生成未完成：{原因}，已改为聊天内联 Markdown 报告。`
