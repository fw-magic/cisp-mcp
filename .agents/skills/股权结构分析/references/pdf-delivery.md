# 股权结构分析 PDF 交付规范

仅在 `SKILL.md` 的 PDF 能力检查全部通过后读取并执行本文件。只复用企业画像的视觉与验收标准；不得引入企业画像的业务章节、字段模型、客户经理话术、数据来源分隔或报告使用说明。

## 生成顺序

1. 完成语义验收后的 Markdown、归一化图数据、路径表和证据映射必须是唯一内容源。
2. 先用最终字体生成仅含“正文测试”和“粗体测试”的临时 PDF，确认常规与粗体映射到不同且覆盖简体中文的 PostScript 字形，并渲染预览确认肉眼可辨。
3. 将同一归一化图数据确定性渲染为 SVG 或等价 PDF 矢量图，再与正文和表格一起排版。禁止使用图像生成模型重绘股权结构。
4. 输出 `output/pdf/{company_name}-股权结构分析.pdf`。中间 JSON、SVG、DOCX、字体测试 PDF 和预览图只作为本次临时文件。

## 固定版式

- 页面使用 Letter，215.9 x 279.4 mm；上、下页边距 20 mm，左、右页边距 25 mm，可用正文宽度固定为 165.9 mm。
- 正文使用宋体或等价中文宋体常规字形，10.5 pt、固定行高 15 pt、段后 4 pt。不得用粗体、字符缩放、缩小字号或压缩行距减少页数。
- 主标题“股权结构分析报告”使用黑体或等价中文黑体，18 pt、黑色、粗体、居中。一级标题使用 14 pt，二级标题使用 12 pt，均为粗体蓝色 `#4F81BD`；一级标题段前 12 pt、段后 6 pt，位于页首时不额外增加段前空白。
- 报告标题下只保留并按既定顺序展示“报告性质、查询时点、目标主体、统一社会信用代码”。四项均居中；普通元信息使用 9 pt、固定行高 12 pt，目标主体使用 12 pt 实际中文粗体。不得增加报告编号、密级、穿透范围或其他头部字段。
- 正文、实体名称、比例、证据说明和表格数据使用常规字重。只允许主标题、章节标题、元信息标签、执行摘要中的证据标签和表头使用实际中文粗体；不得整段加粗。
- 不添加页眉、页脚、页码、企业画像的数据来源分隔线或报告使用说明。内容随有效证据自然分页，不强制压缩到固定页数。

## 中文字体

- macOS 存在 `/System/Library/Fonts/Supplemental/Songti.ttc` 时，正文首选 `STSongti-SC-Regular`（`subfontIndex=6`），粗体使用 `STSongti-SC-Bold`（`subfontIndex=1`）；标题可使用 `/System/Library/Fonts/STHeiti Medium.ttc` 中的 `STHeitiSC-Medium`（`subfontIndex=1`）。
- 其他环境必须选择实际包含简体中文 Regular 与 Bold 的字体，并用字体元数据确认两者 PostScript 名不同且覆盖报告字符。不得把同一 Regular 字形同时注册为 normal 和 bold，不得依赖阅读器合成粗体、描边或重复绘制模拟粗体。
- 使用 ReportLab 时分别注册常规和粗体字体并建立字体族映射。Markdown 的 `**文本**` 只是语义标记；排版时必须转换为实际粗体字形，动态正文先做 XML 转义。
- 中文字体预检失败即停止 PDF 流程并执行 Markdown 降级，不得生成使用乱码、缺字或伪粗体的报告。

## 结构图

- Markdown 中继续使用 `flowchart BT` Mermaid 图；PDF 中的图必须来自同一份 `nodes`、`edges`、`paths` 和证据映射，不得重新推断节点、边、方向或比例。
- 优先把 Mermaid 确定性渲染为 SVG；也可使用能从同一归一化图数据直接生成 PDF 矢量对象的本地工具。必须保留实线事实边、虚线推断边、节点类型样式、文字标签和比例未知提示。
- 图宽不得超过 165.9 mm，按比例缩放且保持文字可读。节点超过 30 个时沿用主图加分图方案，不得把超大图缩小成无法阅读的单图。
- 图形验收时逐节点、逐边与路径表核对方向、关系类型、直接比例、累计比例和证据性质。任一关键标签缺失、重叠、裁切或不可读均视为失败。

## 表格

- 使用黑色 0.5 pt 网格线，无表头底色；表头使用实际中文粗体、左对齐并跨页重复。正文使用 9 pt、固定行高 12 pt、常规字重、左对齐、垂直居中。
- 允许表格自然跨页和长单元格拆分。不得使用 `KeepTogether`、`keepWithNext`、整块容器或手动分页符保护表格、章节或说明；跨页只重复表头，不重复章节标题。
- 按 165.9 mm 可用宽度固定分配列宽：
  - 关键控制路径表：12 / 22 / 42 / 24 / 18 / 22 / 25.9 mm。
  - 控制权核验表：24 / 17 / 17 / 18 / 25 / 22 / 22 / 20.9 mm。
  - 一致行动与隐性关联表：26 / 20 / 35 / 16 / 22 / 22 / 24.9 mm。
  - 关联交易风险表：25 / 24 / 24 / 22 / 15 / 32 / 23.9 mm。
- 不得更改表格列名、增设“状态”列或把证据性质拆成新列。数据过长时换行并自然分页，不得缩小到规定字号以下。

## 生成与验收

1. 语义检查八章顺序、四项报告头部、执行摘要证据标签、控制路径计算、图表一致性、局限与待补证事项；确认没有证据索引、数据来源、接口明细或企业画像专属章节。
2. 使用可控的单一 PDF 生成路径完成排版；直接生成不可用时最多改用一次已经存在且可验收的 DOCX 中转路径，不得因分页问题在多个渲染器之间循环切换。
3. 使用 `pdfplumber`、`pypdf` 或等价工具检查页数、Letter 尺寸、文本可提取性、标题和表头字体、常规与粗体 PostScript 字形以及未替换占位符。
4. 使用 Poppler 或等价工具把最终 PDF 全部页面渲染为 PNG，并逐页检查中文、字号、行高、边距、图形、表格、自然分页、裁切、重叠、黑块和异常空白。除最后一页外，后续仍有连续正文但当前页空白超过可用正文区约三分之一时，视为分页失败。
5. 只有字体元数据和逐页视觉检查均通过时才交付 PDF。验收通过后删除本次全部临时文件，只保留最终 PDF。

## Markdown 降级

- 用户指定 `--format md`、运行环境明确标记为轻型模型、PDF 能力检查失败或 PDF 流程任一步骤失败时，直接在聊天中输出基于同一内容源的完整 Markdown 报告。
- PDF 流程失败时先删除不完整 PDF 和临时文件，再说明：`PDF 生成未完成：{原因}，已改为聊天内联 Markdown 报告。`
- 不循环重试，不交付损坏或未经逐页验收的 PDF，不以 `.md` 文件链接、摘要或局部章节代替聊天内联完整报告。
